# ADR 0001 · First project mapping slice

**Status** Implementer decisions for the local MVP. Founder-approved constraints come from the project brief.

1. **Runtime and database.** Use one Python 3.12 FastAPI process, Pydantic request contracts, SQLite WAL, and a separate outbound Python worker. SQLite gives local developers atomic event/job/audit writes, foreign keys, schema versions and online backups with no database service. PostgreSQL offers better concurrent writers, server identities and multi-instance operation. Revisit before scaling to multiple Hub processes, using network storage, or exceeding acceptable write contention. A broker would add a failure boundary without improving this single-host transaction.
2. **Event sources.** Use explicit authenticated events first, plus opt-in Claude Code `PostToolUse` for successful `Edit` and `Write`. Confirmed the documented event, matcher, stdin JSON, tool call ID and file path against the official hook reference. The hook deterministically filters registered files and hashes content. This observes tool success, not a commit. Git metadata can supply explicit commit events. Signed GitHub push webhooks would add delivery deduplication, signature validation and repository-to-project binding. Defer that adapter until requested. [Claude Code hook reference](https://code.claude.com/docs/en/hooks)
3. **Worker and approval.** Personal hardware may disconnect. Durable leased work lets the worker poll outbound and recover abandoned attempts. At most three claims per retry cycle. Store a constrained evidence-linked proposal and require Founder review before publishing. Review accepts an inference for retrieval without promoting it to a specification. Model and context tuning await measurement on the Founder's actual hardware. [Ollama generate API](https://docs.ollama.com/api/generate)
4. **Retrieval and agent interface.** Start with relational joins and bounded substring search. Benchmark SQLite FTS if ranking or scan time becomes inadequate. Embeddings require additional ingestion, storage and stale-vector handling. The MCP Python SDK negotiates stdio; tools support direct context lookup. Resources and prompts are possible additional interfaces once clients need URI navigation or reusable templates. The MVP tests an SDK client and shares permissions/rules through HTTP. [MCP tools specification](https://modelcontextprotocol.io/specification/2025-11-25/server/tools)
5. **Sequence.** Implement registry and events first, then worker, review and retrieval. Provide status and review by API ahead of a dashboard so the entire acceptance path is executable. Open-ended resource kinds and typed edges allow new providers without granting external credentials.

**Temporary assumptions** One trusted OS administrator, one API process, local filesystem, modest project maps, previously screened public-safe metadata and one tenant per scoped identity. The issuer on the host is under Founder control.

**Recommendations** Measure queue latency, model quality and retrieval relevance with a representative sample before changing the database, model or search strategy.

**Founder approval required** Changes to product direction, official requirements, the authority model, provider-operation scope or any proposed production deployment/domain. The API has no action that grants approval on the Founder's behalf.
